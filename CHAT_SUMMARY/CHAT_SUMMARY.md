# 聊天记录格式与索引

## 1. 记录规则

- 每天一个文件：`YYYY-MM-DD.md`，日期和时间采用 Europe/Berlin 时区。当天已有文件时继续追加，不为每轮另建文件。
- 每轮一个条目：一次用户请求及 agent 的完整回应，在回复结束前记录；讨论、技术解释、方案选择和未修改代码的对话均包含在内。
- 保存结构化摘要：用户要求、结论与决定、实际完成内容、涉及文件、验证结果和未决事项；无对应内容的字段可省略，关键约束可保留原话。
- 使用时间和主题标识条目，并注明聊天 / agent；涉及实验时记录分支和目录。补记时标明补记及已知顺序，不编造原始时间。
- 明确区分“讨论建议”“已确认决定”“已完成”“未验证”；未执行的计划不得写成已完成，未执行的检查不得写成通过。
- 历史条目只追加、不覆盖；纠正通过新条目说明。多人写入前重读文件，同一文件同时仅一名写入者，保留其他人的内容。
- 本文件只保留格式规定和索引；新建每日文件后增加索引，按日期从新到旧排列。项目状态与讨论结论写入对应记录。
- 文件名使用英文，日期文件使用数字与连字符；文档正文使用中文。历史归档保留原文，其旧路径、状态和规则不作为当前操作依据。

## 2. 每日文件模板

```markdown
# YYYY-MM-DD

> 时区：Europe/Berlin

## HH:MM｜讨论主题

- 聊天 / agent：
- 用户要求：
- 结论与决定：注明已确认或讨论建议。
- 实际完成：
- 涉及文件 / 分支 / 实验目录：
- 验证结果：未验证时明确说明。
- 未决事项 / 下一步：
```
